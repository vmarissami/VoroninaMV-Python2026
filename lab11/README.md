# Лабораторная работа № 11. JSON и получение данных по HTTP

Вариант 8 — поиск задач указанного пользователя по подстроке в названии без учёта регистра.

## Запуск

Откройте терминал в папке `lab11`. В Windows вместо `python3` можно использовать `py`.

| Команда | Назначение |
| --- | --- |
| `python3 main.py` | Прочитать `todos.json`, вывести сводку и записать `leaders.json` и `selected.json` |
| `python3 fetch_profile.py` | Выбрать профиль из GitHub или из локального примера |
| `python3 test_analysis.py` | Запустить автоматические проверки без интернета |

Чтобы воспроизвести результаты из архива, введите ID `5` и подстроку `и`. Список лидеров — `[5, 10]`. В `leaders.json` сохраняются задачи с ID `[1, 3, 4, 5]`, в `selected.json` — `[2, 5]`.

## Проверки

Проверки выполнены на Python 3.12.14.

| Сценарий | Ожидаемый результат | Фактический результат |
| --- | --- | --- |
| Учебный набор | Количества `{5: 2, 10: 2}`, лидеры `[5, 10]`, задачи лидеров `[1, 3, 4, 5]` | Совпало |
| Пустой набор и набор из незавершённой задачи пользователя 5 | Количества `{}` и `{5: 0}`, в обоих случаях лидеры и их задачи — `[]` | Совпало |
| Набор из первых четырёх задач | Лидер `[10]`, его завершённые задачи `[3, 4]` | Совпало |
| Отбор для ID 5 по `и` и ` СпИс ` | ID `[2, 5]` и `[5]` | Совпало |
| Неизвестный пользователь и подстрока без совпадений | В обоих случаях `[]` | Совпало |
| Объект вместо списка, повторный ID, отсутствующий `userId`, `completed="false"`, `id=true` | `ValueError` для каждого случая | Все ошибки обнаружены |
| Запись и повторное чтение JSON | Обе сохранённые структуры совпадают с исходными выборками | Совпало |
| Отсутствующий входной файл, неверная кодировка, синтаксис или структура | Программа сообщает причину, оба прежних результата сохранены | Совпало, результаты проверены побайтово |
| Повторный ввод | `abc` и `0` отклоняются, принимается ID `5`. Пробельная подстрока отклоняется, `И` даёт ID `[2, 5]` | Совпало |
| Локальный профиль | `Логин: demo` | `Логин: demo` |

## HTTP и локальный профиль

Адрес `https://api.github.com/users/{login}` указывает на профиль пользователя по логину. `urlopen()` отправляет GET-запрос для чтения профиля с таймаутом 10 секунд. Обработчики различают HTTP-статус ошибки, сетевой сбой, некорректные данные и ошибки файлового доступа. Успешно полученный профиль сохраняется в `profile.json`.

Проверочный запрос для `octocat` завершился статусом HTTP 403. Для сдачи использован локальный учебный профиль из `profile_sample.json`. Пункт 2 читает его через `json.load()` и выводит `Логин: demo`. Поле `name` сохраняется как `null`. Оба режима используют функцию `show_profile()`.

## Пояснения к защите

- Синтаксис проверяет JSON-декодер. Структуру задач, типы полей и уникальность идентификаторов проверяет `validate_todos()`. Проверка `type(value) is int` исключает логические значения из идентификаторов.
- Идентификаторы сравниваются как числа. Для выборок выполняется обход исходного списка, поэтому сохраняются порядок записей и их поля.
- Проверка структуры и расчёт результатов выполняются до открытия выходных файлов. Импорт модулей не запускает ввод, запись файлов или сетевой запрос.
